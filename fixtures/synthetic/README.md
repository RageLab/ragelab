# Synthetic YMAP fixture

`simple.ymap` is generated by `scripts/generate_synthetic_ymap.py` and contains no Rockstar/third-party asset data.

It is intentionally minimal and only exercises fields currently parsed by `rage-ymap`:

- META root `CMapData`;
- one pointer-array entity;
- one `CEntityDef`;
- one physics dictionary hash;
- map `name`/`parent` hashes.

Expected semantic values are in `simple.expected.txt`.

Regenerate with:

```bash
python3 scripts/generate_synthetic_ymap.py
```

This fixture does **not** prove compatibility with real GTA V files. It is a deterministic regression fixture; real private fixtures are still required.

## `ymap-relations/`

Generated by `scripts/generate_synthetic_ymap_relations.py`. These four YMAPs reuse the `simple.ymap` META layout and change only `CMapData.name`/`parent` to form a deterministic graph: one parent, two direct children and one grandchild. They exercise structural reverse-parent closure without relying on filename conventions such as `_strm`/`_long`/`_critical`.

## `simple.ytyp`

Generated by `scripts/generate_synthetic_ytyp.py`. The YTYP has one base
archetype whose name hash (`0xEF3DBDA5`, `test_archetype`) matches the entity in `simple.ymap`; its model/dictionary hashes are deterministic `joaat` values listed in `simple-ytyp.expected.txt`.

## `stream/`

The `stream/` subdirectory combines copies of the generated YMAP/YTYP with empty
placeholder `.ydr/.ydd/.ytd/.ybn/.ycd` files. Their filenames are deliberately
chosen so GTA `joaat` hashes match the synthetic YTYP references. It also contains
`gtxd.meta` plus two empty parent YTD placeholders to exercise a two-hop texture
parent chain. The files are for dependency-index tests only; they are not valid
model/texture/collision resources.
