# Quality and Compatibility Gates

RageLab quality evidence is layered. A successful parser or semantic reopen is not equivalent to independent CodeWalker acceptance, GUI rendering, or GTA/FiveM runtime behavior.

## Fixture policy

### Committed fixtures

- Prefer small, deterministic, synthetic bytes generated by scripts or test builders. Keep each fixture focused on one invariant (header, pointer, descriptor, vertex layout, texture encoding, dependency edge, writer behavior).
- Committed compatibility-matrix paths must resolve below `fixtures/synthetic/`; `scripts/check_hardening.py` rejects absolute paths, private fixture paths, missing/empty fixtures, duplicate case IDs, and layers outside the declared matrix.
- A synthetic fixture must document its generator and the behavior it is intended to prove. Regenerate it deterministically and validate it with `scripts/validate_synthetic.py` (plus the format-specific validator where present).
- Bytes with an explicit redistribution grant may be committed only when the grant and provenance are recorded. Otherwise treat them as external.

### External and installed assets

- Personally owned or otherwise authorized proprietary files belong under the ignored `fixtures/private/` directory or in a user-controlled external fixture location. Tests must open them read-only and must not copy bytes into committed goldens, CI artifacts, snapshots, or logs.
- External tests are opt-in through environment variables such as `RAGELAB_TEST_YFT` and `RAGELAB_SHADER_TEMPLATE_YFT`. Missing variables mean the corresponding tests are not run; they are not silently replaced with a synthetic PASS.
- Installed GTA probes are metadata-only and optional. They must not make the public repository or CI depend on a local game installation.
- Never modify installed GTA/FiveM files as a test setup action.

## Test and evidence tiers

| Tier | What it proves | Required status |
|---|---|---|
| Parser / structural | Header, bounds, pointer, counts, descriptors, supported layout and explicit rejection of malformed/unsupported input | Required CI |
| Semantic round-trip | The writer's output can be reopened by RageLab and the relevant metadata, topology, segments or payloads survive comparison | Required CI where a writer exists |
| Deterministic golden | Stable, synthetic output projection and repeatability for fixed inputs/options | Required for versioned contracts and deterministic writers |
| Independent CodeWalker Core parser | An independently implemented parser accepts the output | External optional until a redistributable/read-only adapter with a documented machine contract is wired into CI |
| CodeWalker GUI | The actual desktop application loads and displays the asset | Manual external acceptance; distinct from parser success |
| GTA V Legacy runtime | Actual in-game behavior on Legacy | **WAIVED** for the previously waived standalone gate; explicit user approval is required to reopen |
| FiveM runtime | Actual behavior in a user-owned FiveM environment | Manual external acceptance, separately recorded |

A CLI inspection result, a successful YDR semantic reopen, or a JSON `runtimeRenderable=false` field must never be promoted to CodeWalker GUI or game-runtime acceptance.

## Deterministic mutation / property-style smoke tests

The normal workspace suite contains bounded, deterministic mutation corpora:
- GLB inspection/geometry: 160 mutations of a valid synthetic GLB plus 160 short pseudo-random inputs; successful decodes assert source hash/length and primitive vertex/index cardinality invariants.
- RBF: 256 bounded mutated/random inputs, including truncation and a valid magic prefix.
- RSC7: 256 fixed-size header mutations and 128 mutations/truncations of a resource with a fixed, bounded decompressed-size declaration.
- Steam discovery metadata: 256 mutated/truncated inputs across ACF/VDF field extraction and manifest parsing. Oversized file reads are rejected before unbounded allocation.

These are deterministic *mutation smoke tests*, not coverage-guided fuzzing. They catch panics and selected invariants in CI, but do not claim libFuzzer/AFL coverage, exhaustive state exploration, or a proven absence of parser bugs. A future coverage-guided target should reuse the same synthetic corpus and keep all inputs size-bounded.

## Resource budgets

These are hard parser/decoder caps, not recommended asset sizes. Reaching a cap must fail closed with an explicit error before large allocations where the parser can know the count or size in advance.

| Subsystem | Current cap |
|---|---:|
| GLB file bytes | 512 MiB |
| GLB vertices per primitive | 2,000,000 |
| GLB indices per primitive | 6,000,000 |
| Encoded image, per image | 128 MiB |
| Embedded image bytes, aggregate | 512 MiB |
| Image pixels, per image | 64 Mi pixels |
| Image width or height | 16,384 |
| RBF nesting depth | 256 |
| RBF nodes | 1,000,000 |
| YDR models / shaders | 4,096 each |
| YDR geometries per model | 16,384 |
| YDR vertices / indices per geometry | 2,000,000 / 6,000,000 |
| YDR vertex payload | 256 MiB |
| YBN children / vertices / polygons | 16,384 / 2,000,000 / 4,000,000 |
| YBN flattened vertices / indices | 4,000,000 / 24,000,000 |
| YTD textures | 16,384 |
| YTD encoded texture payload | 2 GiB |
| YTD decoded RGBA | 256 MiB |
| YTD generated RGBA mip payload | 512 MiB |
| Steam library/app manifests | 1 MiB per file |
| CitizenFX.ini | 256 KiB |
| YDR names / YTD texture names | 1,024 / 4,096 bytes |

Renderer budgets (asset and texture caches) are tracked separately in `fixtures/hardening/budgets.json`. They are not parser caps.

## Local gates

Run the same locked Rust gates as CI:

```powershell
python scripts/validate_synthetic.py
python scripts/validate_synthetic_ymf.py
python scripts/check_hardening.py
cargo fmt --all -- --check
cargo check --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace
```

The CI workflow also performs exact visual-regression renders on synthetic fixtures and a Chromium/Firefox/WebKit web matrix. Dependency resolution is locked for every Rust build/check/lint/test step.

## Compatibility matrix and waivers

`fixtures/hardening/compatibility-matrix.json` is the machine-readable source for synthetic compatibility cases and gate status. `scripts/check_hardening.py` validates the required tiers and specifically asserts that `gta-v-legacy-runtime` remains `waived` with `requiresExplicitApprovalToReopen=true`.

A change to the waiver, required CI gate, hard resource budgets, or fixture policy requires review of this document, the matrix, and the hardening checker in the same change. External acceptance evidence must identify the validator/application, exact build/version, fixture provenance, operation performed, and result; do not infer acceptance from a different tier.
